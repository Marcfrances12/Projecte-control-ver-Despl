Desarrollo con Git Flow

Documentación del proceso del curso de JavaScript aplicado a elementos HTML.

1. Metodología: Git Flow

Git Flow es una forma de organizar el trabajo con ramas. Cada tipo de tarea tiene su propia rama, y así el código estable queda separado del que está en desarrollo:

  • main: versiones estables y publicadas.
  • develop: donde se junta el trabajo en curso.
  • feature/*: una funcionalidad nueva.
  • release/*: preparación de una versión antes de publicarla.
  • hotfix/*: corrección de algo ya publicado.

La usamos porque el equipo es de tres personas y el proyecto tiene varias secciones: cada una se desarrolla por separado, se evitan conflictos y el historial queda ordenado para el cliente.

2. Proceso realizado

Usuario 1: repositorio y estructura inicial

Se crea el repositorio en GitHub con las ramas main y develop. Sobre develop se añade el boilerplate (HTML5 Boilerplate) y se adapta la página con la cabecera, la barra de navegación, el texto del Home y el footer.

Usuario 2: dos features

Crea feature/contingutHTML con la sección "Modificar contenido HTML" y feature/atributsHTML con la sección "Modificar atributos HTML". Cada una se fusiona en develop mediante un Pull Request.

Usuario 3: feature y release v1.0

Crea feature/estilsCSS con la sección "Modificar estilos CSS". Después, con las tres features en develop, crea release/v1.0 y la fusiona en main con la etiqueta v1.0.

Usuario 1: hotfix

Durante las pruebas mejora la sección de contenido HTML en hotfix/milloresV_1_0, que sale de main y se fusiona en main y develop.

3. Problemas resueltos

  • Pull Request hacia la rama equivocada: uno iba a main en lugar de develop. Se creó otro con la base correcta.
  • Push rechazado: las ramas locales estaban desactualizadas respecto a GitHub. Se sincronizaron con el repositorio remoto y se rehízo el cierre de la release.
  • Conflicto en index.html: el menú se había modificado en dos ramas. Se conservó la versión con los cuatro enlaces correctos.
  • Etiqueta v1.0 mal colocada: se borró y se volvió a crear sobre el merge de la release.
